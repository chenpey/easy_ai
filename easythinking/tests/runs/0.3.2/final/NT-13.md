## 回复

这确实够磨人的。直接看代码：

`arr` 长度是 `len` 时，合法下标是 `0 … len-1`，`arr[len]` 永远越过最后一个元素一格，所以必然越界。

按你的意图，改法有两种：

- **想访问最后一个元素**：用 `arr[len - 1]`（或 `arr[arr.length - 1]` / `arr.at(-1)`，`at(-1)` 空数组时返回 `undefined` 而不是抛错）。
- **想追加一个元素**：不要用下标赋值，用 `arr.push(x)`；在 JS 里 `arr[arr.length] = x` 也能追加，但越界写会静默扩容（数组变长而不报错），所以这类 bug 往往只在定长数组/`TypedArray`/C 系语言里炸出来。

两个常被忽略的诱因：

- `len` 来源是「上一个元素的下标」而不是「元素个数」，混用会正好差 1。
- 循环里用 `<=`：`for (let i = 0; i <= arr.length; i++)` 会在最后一轮取到 `arr[len]`。

如果你把出问题的那几行（`len` 怎么算出来的、数组怎么构造的）贴出来，我可以确认是长度口径错还是边界条件错，这两种的修法不一样。
