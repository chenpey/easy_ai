# 折叠评测（调整子代理角色前的门槛）

适用：废除或折叠 `developer`、`designer` 等子代理角色，或放宽独立审查触发条件之前。原则：先有评测，一次只折叠一个角色；折叠版不差才折叠，更差则保留。本文不属于运行时规则，不随 skill 安装。

## 对照臂

- 基线臂：同一待评版本，`developer` 显式配置为与主代理相同的实际模型与推理深度，委派开发者。
- 折叠臂：同一版本，`developer` 的模型与深度均为 `inherit`，模型阶段 0 由主代理写入。两臂固定 designer、reviewer、upgrades、宿主、任务集与预算；记录实际模型和深度，不能用“低成本开发模型对高能力主代理”证明角色折叠收益。
- 本评测只比较阶段 0 的开发角色是否委派。进入模型升级阶段时两臂都委派配置的开发者；要改变升级委派规则须另设实验版本，不能把违规执行计作折叠成功。每次只改一个变量，不新增运行时配置键。

## 任务集（通用基准走不到这些分支，需专项构造）

1. full + 设计门控 + 多阶段施工（`designer` 为 `inherit`）：多个独立验收阶段可始终处于模型阶段 0，不因交付阶段增加强制委派。
2. 升级触发：确认根因后首次修复失败，覆盖单级与两级 `upgrades`；分别报告升级前的角色差异与升级后的共同委派行为、预算继承。
3. 上下文膨胀：长任务验证委派例外；折叠臂触发例外后单列结果，不冒称全程主代理写入。要评测禁用此例外，另设实验，不混入本组因果比较。
4. 对照：quick、normal 各若干，确认无回归。
5. 种子缺陷：含已知 P1/P2 的改动，度量审查召回。

## 指标与判据（初始值，须用基线运行校准）

- 硬门：任务通过率（以项目脚本与红绿证据为准）相对基线下降不超过 5 个百分点；种子缺陷召回不低于基线；“原本通过的流程被破坏”的任务数为 0。
- 观测（不作门）：总成本、耗时、尝试次数、主代理上下文峰值。
- 每臂次数按基线方差确定；样本不足时结论记“证据不足”，不放行折叠。

## 决策与记录

- 折叠臂通过全部硬门才可折叠；任一硬门未过则保留该角色。
- 结果写入 CHANGELOG：对照臂、任务集、次数、指标、结论与已知限制。
- 真实模型回放有随机性，只作观测与放行依据，不进 CI 门禁；离线替身只验证验收机制。

## 并行评测

用于放行或放宽 full 并行写入（`workflow.md#并行执行`）。未有通过记录时正式任务默认串行；在用户明确授权的隔离评测中比较串行与并行调度，不把该授权当作正式放行。两臂版本、开发者实例数、实际模型/深度、宿主、隔离资源与任务集相同，仅改变执行是否重叠；保留基线快照和配置摘要，不能用角色数量或模型能力差异代替并行收益。

- 任务集：full 的 ≥2 个独立片；normal 对照保持单写、仅只读并行；隐藏依赖、共享生成物或锁文件任务必须串行处理冲突部分。另覆盖脏基线迁移、整仓验证统一停写、审查依赖变化失效、增量余量耗尽、跨片同因预算和模型升级暂停并行。
- 硬门：通过率相对串行臂下降不超过 5 个百分点；越界写入、验证期间修改其输入、沿用失效审查或超预算次数均为 0；片间冲突导致的返工任务数不高于基线。
- 收益（并行臂须真有收益才放行）：端到端耗时明显低于串行臂，且成本增幅可接受；阈值为初始值，须用基线运行校准。
- 观测：并行宽度、单片耗时、冷启动占比、限流次数、集成冲突与退回次数、令牌成本。
- 放行记录必须绑定版本、宿主与任务类型；缺少真实重叠事件、样本不足或硬门失败均不放行。当前协议尚未实跑，不能宣称性能收益或通用并行能力已验证。
