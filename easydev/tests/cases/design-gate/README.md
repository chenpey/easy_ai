# design-gate

流程状态机中可判定的部分：`references/routing.md` 的 normal 一次独立定向审查与转 full 继承；`references/design.md` 的启用门控、`d/3` 与 `r/5` 记账、施工闸与停止条件；以及给定宿主能力时的分派形态。

```bash
bash tests/cases/design-gate/run.sh
```

## 覆盖什么

- **门控五项判定**（12 组 fixture）：跨边界（包数、层数、同包多文件不触发）、公共契约或持久数据、多阶段施工（≥2 实施实例或 ≥2 独立验收阶段；交给独立审查者不触发）、多方案（候选两条启用条件同时满足，或用户显式要求对比）、高风险边界。包括「基准局部任务不启用」这一可达成性回归。
- **normal 状态转换**：恰好一个不同实例回传非空报告才可交付；无审查、作者自查、空/纯空白报告或第二个审查实例不能满足/绕过一次审查，前三种无效输入不消耗唯一名额；范围内 P2 转 full 时首个审查继承 `r=1/5`，修复尝试不重置。
- **记账与停止**：不启用门控时 `d` 不计；候选第二轮未获用户 opt-in 被拒；候选两轮后设计审查报缺陷无轮可用而停止；受阻轮不算缺陷已关闭；剩余 `r` 不足两轮禁止单开设计重审；阶段增量审查最多 3 轮（余 2 轮给完整审查与复审）；完整初审报缺陷却无复审轮次时停止；施工期 `d` 用尽时停止；**升版重写不消耗 `d`**。
- **宿主能力替身**（外部边界，9 组）：`inherit` + 有委派（主代理设计、施工必须委派开发者）；`inherit` + 无委派（兜底、不记 `d`/`r`）；独立 `designer` + `developer` 为 `inherit`（主代理可自行实施）；独立 `designer` + `developer` 非 `inherit` 或处于升级阶段（仍须委派，不得绕过配置）；`designer` 模型不可用（暂停、不回落主代理）；用户禁止委派；宿主强制继承上下文。
- **受阻轮处置**：默认停闸且不得声称闭环完成；用户显式豁免可放行，但须标「设计环节未独立审查」且仍不得声称闭环。
- **文档契约**（6 组）：账本模板含门控判定/冻结时间/设计者/两本账；报告段含门控、冻结时间、建议通道、施工闸；预算段含「候选第 2 轮留给设计审查」与「重写不计轮」；按需加载表链接到门控正文；B60 含升级进入与受阻两个对照；门控仍为五项。这一组把审计里靠人眼发现的字段缺失与口径漂移变成回归。
- **可达性枚举**：多方案任务在「候选轮数 × 设计审查是否报缺陷 × 是否 opt-in」六种组合下的结局。结论：默认分配（候选 1 轮）下全部组合都能闭环完成；只有用户 opt-in 用满 2 轮且设计审查报缺陷时才停止，且为显式停止而非静默失败。

## 材料边界

`gate_model.py` 是 `references/routing.md` 与 `references/design.md` 的可执行断面：normal 转换、判定、记账与分派形态写在这里，fixture 写在 `verify.py`。两者与文档不一致时，属本用例缺陷而不是文档缺陷——先改这里，再核对文档。

**替身（mock）的合法范围**：宿主是否具备委派能力、`designer` 模型是否可用、上下文能否隔离、审查实例是否受阻、设计审查报出几项什么级别的发现——这些是**输入**，属外部边界，可以替身。被测对象是「给定这些输入，规则要求做什么」。

## 未覆盖什么

- **模型是否遵守规则**：替身能证明「如果宿主是这种状态、审查报出这些发现，规则要求如此」，**不能**证明任何 Agent 会照做。后者需要真实模型回放。
- **受阻的产生条件**：本用例只固定「受阻发生了以后怎么办」，不产生真实受阻（需要宿主反复失败）。
- **无委派能力的真实宿主**：兜底分支的决策已固定，但没有在真实无委派宿主上实跑过；该模式按规则不记 `d`/`r`。
- **实例隔离的实现**：真实分派、上下文隔离、只读约束不在本用例范围内。
- **数据库与迁移行为**：真实回放中那条 P1 是设计层结论，没有真实 DB 验证。

## 真实回放记录（2026-10-24，`designer=inherit`、`reviewer=codex/gpt-6.1-sol:high`）

在临时目录用一份真实需求（订单批量导入：跨三层、改表结构、支持部分失败回滚）走完整链条：

1. **门控判定**：命中「跨边界」「公共契约或持久数据」「多阶段施工」3 项 → 启用。
2. **设计产出**：`design.md` v1（首行带版本与冻结时间）+ `ledger.md`，六个内容小节与账本的每个字段都填得进去，无空位、无冗余字段。
3. **独立设计审查**：真实分派独立实例。结果：1 项 P1（迁移按最小 ID 删除历史重复 `order_no`，会丢掉不同业务字段的记录；而用户只要求「导入时跳过重复」，未授权删历史）+ 3 项**明确不定级**的建议。硬约束确实拦住了把无失败路径的顾虑定成 P 级。
4. **施工闸**：P1 未关闭 → `冻结` 报「仍有 1 项未关闭，不进入施工」。
5. **v2 收敛**：重写不计轮，v2 的设计审查为 `d=2`；收敛后 `d=2`、`r=2` 闭环完成。结论与本载体的状态机预测一致。
