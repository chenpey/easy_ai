# design-gate

流程状态机确定性断面复验：覆盖 `references/workflow.md` 的 normal 定向审查、局部 P2 修复与转 full 继承；`references/design.md` 的启用门控、`d/3` 与 `r/5` 记账、施工闸与停止条件；以及宿主能力替身分派。

```bash
bash tests/cases/design-gate/run.sh
```

## 覆盖什么

- **门控五项判定**（14 组 fixture）：跨边界、公共契约或持久数据、多阶段施工（≥2 独立验收阶段）、多方案对比、高风险边界。覆盖局部改动与纯注释/日志措辞的免启用场景。
- **normal 状态转换**：不同实例回传有效报告方可交付；作者自查或第三次审查被拒；首轮仅局部 P2 时允许一次修复与定向复审（通过则 2 次审查完成）；未关闭或非局部 P2 转 full 继承轮次。
- **记账与施工闸**：未启用时不计 `d`；候选第 2 轮需用户明确 opt-in；升版重写不消耗 `d`；剩余 `r<2` 时禁止单开设计重审；施工闸按必关项放行（P3 建议不阻断）。
- **宿主能力替身**（12 组边界）：覆盖 inherit 模式自行施工/暂停受阻、独立 designer 委派、模型不可用报错、用户显式禁止委派兜底等。
- **受阻轮处置**：默认停闸且不得宣称闭环；用户显式豁免可放行但须标注未独立审查。
- **文档契约回归**（55 项契约 + 11 组机制自检）：锁定设计账本、施工闸、局部 P2 判定、直接调用方范围、并行判断门槛、开工核实角色配置等关口短语，杜绝口径漂移与跨节挪移。
- **多方案可达性枚举**：枚举候选轮数与缺陷反馈的 6 种组合，验证默认分配均可闭环，满 2 轮报缺陷时显式停止交用户裁决。

## 材料与边界

- `gate_model.py`：`workflow.md` 与 `design.md` 的可执行状态机断面。
- `verify.py`：驱动 127 项确定性断言（14 组门控判定 + normal 状态流 + 记账 + 12 组宿主替身 + 55 项文档契约 + 11 组机制自检 + 6 组可达性枚举）。
- **未覆盖**：真实模型的自律性（需行为回放）、宿主动态调度与网络隔离。

历史演进与验证边界见 [CHANGELOG](../../../CHANGELOG.md)。
