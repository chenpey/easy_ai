# audit-overflow

B65 规约“大仓分片审计与超过 20 条发现处理”的确定性复验。固定规则：正文上限 20 条、附录保留全量发现、正文外 P1 必须在摘要披露，且分片覆盖须明确标注已审、部分及未审状态。

```bash
bash tests/cases/audit-overflow/run.sh
```

## 覆盖什么

- **发现条目截断**：固定场景含 23 条确定发现（21 个 P1、2 个 P2）；正文收录前 20 条，附录保留全部 23 条完整记录。
- **溢出 P1 摘要披露**：摘要逐条披露正文外溢出 P1 的具体影响与附录入口；验证多个溢出 P1 不会被覆盖丢失。
- **分片状态诚实披露**：每片状态取值限定为 `reviewed`/`partial`/`unreviewed`；`coverage` 必须列齐审计范围内的全部分片（含零发现片），漏列分片与空覆盖均不得声称全仓审完；局部片须列未覆盖范围、未审片须列原因；不要求三种状态同时出现。
- **违约拦截**：正文超过 20 条、附录漏记、溢出 P1 缺漏或虚假全覆盖均会被断言拒绝。

`audit_model.py` 为 `references/review.md` 与 B65 的断面模型，`verify.py` 执行独立验收。

## 未覆盖什么

- 真实模型分片执行自律性与缺陷挖掘能力。
- 跨分片复杂接口与真实大仓工具执行质量。
