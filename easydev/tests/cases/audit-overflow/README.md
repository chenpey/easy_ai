# audit-overflow

B65“大仓分片与超过 20 条”的确定性复验。检索结果不替代真实仓库审计；本载体固定规则要求：正文最多 20 条，附录/审查产物保留全部发现，超正文 P1 必须在摘要披露，部分覆盖必须列已审、部分、未审。

```bash
bash tests/cases/audit-overflow/run.sh
```

## 覆盖什么

- 固定场景含 23 个确定发现：21 个 P1、2 个 P2；正文取前 20 个 P1，附录保留全部 23 条完整记录。
- 摘要逐条披露正文外 P1 的影响与完整记录入口；固定场景有一个溢出 P1，22 P1 对照另验证多个溢出 P1 不会互相覆盖。
- 分片覆盖同时记录 `reviewed`、`partial`、`unreviewed` 及后两者的原因；存在后两者时不得声称全覆盖。
- 正文超过 20 条、附录少 1 条、缺少或写错任一溢出 P1 影响、任一覆盖状态/原因缺失或虚假声称全覆盖时均失败。

`audit_model.py` 是 `references/review.md` 和 B65 的可执行断面，`verify.py` 用独立验收逻辑检查其产物及变体。两者与正文不一致时属本用例缺陷，先修正本用例再核对文档。

## 未覆盖什么

- 真实模型会不会按分片范围审计、能否发现全部缺陷。
- 真实大仓库的跨片接口、代码证据和工具输出质量。
- 真 token、耗时、费用以及“20 条”之外的用户体验。
