# 环境与调用适配

仅在委派能力不确定、需要核对模型/深度支持、调用失败或需要能力降级时读取；常规分派按 [models.md](models.md) 即可。模型分配按 [models.md](models.md) 的路径优先级选择配置，这里不维护第二份模型表；配置读取失败按该规则暂停分派，不用继承默认值绕过。

先读取当前宿主暴露的工具说明：是否允许子代理、可用模型、深度参数、上下文隔离选项、写入权限和并发限制。使用真实工具接口，不硬编码旧的 `collaboration.spawn_agent`、参数名或插件版本路径；不通过 CLI 或另建用户会话规避宿主限制。

- 用户明确指定的模型、供应商和禁止委派约束优先。预设模型仅在工具允许覆盖、确实可用且已有对应授权时使用；skill 的文字不能扩大工具权限。
- 配置或用户指定的具体模型与深度是硬性要求：工具不允许按该值覆盖时暂停相关分派并报告受阻，不得改用继承模型，也不得只在说明后继续。只有选中配置为 `inherit`（或没有任何配置来源）时才使用工具规定的继承模型，并保持独立实例和只读审查。
- 若已开始使用的供应商因权限、额度、模型不存在或网络失败而不可用，先分类故障；不要静默换供应商、切配置或无意义重试。仅按用户已有授权使用替代，否则完成不依赖该调用的工作并说明阻塞。
- 跨供应商交接只给必要代码、需求和证据，不发送凭证或完整会话；不得自动修改 API key、默认模型、全局开关或连接设置。
- 没有子代理能力或用户禁止委派时按下方能力降级执行；调用失败先分类，已有设计审查受阻的施工闸仍按 design 处理，不能用降级自动豁免。

配置模型不授予第三方访问权限，也不授权安装供应商或设置密钥。模型和推理深度都须核对工具支持范围；用户明确锁定的要求无法满足时报告受阻，不擅自替换。记录实际模型/深度：先取工具返回值，再查宿主允许访问的运行记录或事件；确无记录或不可访问时才注明未知及原因，不能把请求值当作运行证据。

选择不继承完整会话的选项时，以实际接口支持为准；不支持该选项就说明隔离限制，不伪称干净上下文。角色至少用不同实例分离，参与某次实现的实例不得审查自己写的结果；启用 [独立设计环节](design.md) 时设计者、实现者、审查者两两不同实例。

`designer` 配置了具体模型但宿主不支持时，同样暂停设计分派并报告受阻，不回落主代理、不用继承模型替代；只有 `designer` 为 `inherit` 或未配置时才由主代理执行设计，并在报告标注「设计者=主代理」。

创建子代理不等于创建新的用户聊天。仅在用户明确要求新聊天时使用聊天管理工具。

## 能力降级与审查包

分别记录三种状态，不把工具限制改写为低风险：

- **不同实例且上下文独立**：正常独立审查。
- **不同实例但继承上下文**：可以按原档位审查，标“独立实例、上下文隔离受限”，不声称清空了上下文；设计/实现/审查的实例分离仍须满足。候选互不可见另按 candidates 的条件判断。
- **同一实例或无委派能力**：在授权内实施与对抗式自查，标“自查（非独立）”；从需求重新推导失败输入、边界和反例，核对测试是否能拦截，而非复述实现理由。不得称 normal 独立审查通过或 full 闭环完成。

自查降级必须给可交接审查包，按 [任务目录规则](baseline-safety.md#任务目录与恢复) 保存，至少包括：原始要求/验收、基线及当前版本、完整任务 diff（含新增文件）、直接调用方与必要契约材料、验证命令/结果及证据、未决发现/风险/已用预算。材料足以供另一会话或人工核对；只给作者摘要或本机失效路径不够。敏感内容脱敏，原始快照按权限保护，不自动上传、另开聊天或发送。

已启动的独立审查因模型/额度/网络失败时先保留现场和已有预算，完成不依赖阻塞的工作；不能把受阻轮记为通过，也不能借“无能力”关闭已有缺陷或绕过冻结设计的施工闸。重派/替换具体模型/放弃必需审查依照用户已有授权，无授权时再请求决定。无工具能力的初始兜底不制造审查轮数，已用轮数不退还。

审查包交付不等于缺陷关闭。P0/P1 争议仍未独立确认时保留未关闭；确认缺陷、验收缺口或高影响待验证风险按 execution 标部分完成。没有已知缺陷但缺独立审查时，报告“实现与自查完成，独立审查待补”。

## Google Antigravity（AGY）

- 安装位置按 [官方 Skills 文档](https://antigravity.google/docs/skills)：项目级为 `.agents/skills/easydev/`；App/IDE 用户级为 `~/.gemini/config/skills/easydev/`，CLI 用户级为 `~/.gemini/antigravity-cli/skills/easydev/`。保持 `SKILL.md` 与 `references/` 等运行时文件的相对位置；安装步骤见 [仓库安装指南](https://github.com/chenpey/easy_ai/tree/main/easydev#安装)。
- 先确认宿主已发现技能，App/CLI 可通过 `/easydev` 显式调用。目录存在或文档兼容不代表当前宿主已加载、激活或通过行为回归。
- 原生委派按 [官方 Subagents 文档](https://antigravity.google/docs/subagents)：使用当前工具实际暴露的 `invoke_subagent`；自定义代理的 `subagent` 必须允许调用。将开发/审查角色映射为独立实例，审查仅给必要材料与只读权限，不因工具同名假定各版本参数相同。
- 配置中的模型 ID、推理深度及工作区隔离选项须逐项核对宿主工具能力；不能把模型层级当成任意供应商 ID，或静默忽略不支持的设置。无法满足时沿用本文件的受阻规则，不虚称独立审查通过。
- Antigravity 的配置来源、优先级与完整路径统一见 [模型配置](models.md)，不附带专用模型示例。模型层级、推理深度及覆盖是否生效须以当前 `invoke_subagent` 工具接口和宿主指令为准，未回传时按运行记录或事件核对，确无可访问记录才标未知并说明原因。

## Codex 与 Pi

- **Pi**：通过 `subagent` 工具分派，字段为 `agent`、`task`、可选 `model`（`provider/id`）、`workflow`、`cwd`；字段以宿主当前工具 schema 为准，版本差异时按实际 schema 传参；分派后按运行记录或事件核对实际模型与推理深度，不把请求值当实际值。
- **Codex**：以当前工具说明中的字段为准，先用最小调用确认返回值可读，再按正式任务分派；不硬编码旧工具名或旧参数。
- 两者都必须做到「审查实例只读、与实现实例不同」；返回值或记录不可读时按本文件的受阻规则处理。
