# 执行与验证

本模块用于 full、normal/quick 超出内联核心、性能优化/效果声明或需要完整验证/完成边界的工作；仅为性能任务加载时聚焦「测试选择」的性能要求，不改变风险分流。其他干净局部 quick 使用 [SKILL.md 的 quick 执行核心](../SKILL.md#quick-执行核心)。任务基线、敏感快照与恢复见 [baseline-safety.md](baseline-safety.md)。

## 最小充分实现

先找现成模式和全部受影响入口，定位并修复**实际违反契约的位置**（共享解析器、基类、状态机或 helper 失守时修共享源头并核对读/写、序列化/反序列化、同步/异步等对称分支；特定调用方传参或使用违约时修调用方，不在无辜下游打掩盖上游错误的表层补丁）。范围与难度按任务定，不看文件数；不顺带清理历史债。改动前确认可能破坏或暴露的用户数据及会失效的调用方。

按序取第一个能完整解决问题的方案：
1. 需要存在吗？没人要求的功能、选项和灵活性直接跳过并用一行说明（不得跳过用户明确要求的内容；高风险改动仍按规则进入 `full`）；需求含糊但核心工作与验收唯一时先做完成核心工作的最小版本；存在会改变结果的互斥解读时按 [选项式澄清](planning.md#选项式澄清) 一次问清，不按猜测实现。
2. 本项目已有实现（helper、组件、服务、既有模式）？按周围用法复用。
3. 标准库或平台能力？优先使用，除非项目已有更合适的自家实现。
4. 已安装依赖？用现成的，不为少写几行引新依赖；新依赖须解决现有能力无法合理覆盖的需求。
5. 选择一眼能懂的直接写法；简单表达式用一行，分支与状态变化展开写清。
6. 补齐需求所需的最小代码，以理解和修改成本衡量简洁。

- 懒在方案、不懒在改动：受影响的调用方、测试、配置、导出一次补齐，不留半成品。
- 复用项目分层、接口与约定，值保持平台原生形式；抽象仅服务复用或降复杂度。命名表达业务含义，职责集中；删除冗余保留必要行为，移动/合并代码保留原错误处理与校验。同规模方案选边界更正确的。
- 注释简要解释代码无法直接表达的原因、单位、约束、边界或取舍，关键算法与安全条件写全；行为变化时同步说明，保留有效解释与无关已有注释。已知取舍在注释或文档中说明限制与升级条件，不用固定注释前缀，也不用 `TODO` 掩盖验收缺口。
- **不得削减**：信任边界输入校验、防数据丢失的错误处理、安全与隐私、可访问性、真实硬件校准及用户明确要求的内容。

## 文档与人工接手

在项目已有位置维护一份权威说明，用正向陈述讲清当前行为、用法、适用条件与异常处理，保留关键契约、参数与单位、必要步骤、验证方法和已知限制（明确禁止条件仍直说）。实现变化时同步注释、示例和文档；相同规则用链接引用，历史记录保留当时事实。

交付前检查接手者能否找到入口、理解约束并运行验证；优先修正理解障碍、失实说明和重复逻辑，不把代码/注释/文档篇幅当质量目标或触发范围外重写。

## 修复尝试与路径切换

一次尝试从提交候选修复开始，记录验证结果（成功、失败、证据不足或环境受阻）。失败先回退取证，下一次须有新证据；调查和环境故障不计次。次数与升降级以 [尝试预算](routing.md#尝试预算) 为唯一事实源，不能在进入 full 时重置。

预算耗尽时报告目标不变量、已暴露的耦合位置、最小修复是否成立及剩余缺口，不因失败次数自行推断必须重写架构。full 另受 [审核预算](orchestration.md#升级与停止) 约束。

## 处理审查反馈

开发者先对照需求、代码与测试核实发现；信息不足由主代理补上下文或最小验证，仅需用户决定的部分按 [选项式澄清](planning.md#选项式澄清) 交主代理合并提问，独立已确认修复继续。按“阻断/安全 → 简单 → 复杂”安排优先级，同因同解或同一验收行为的修复成组完成，再按 [测试硬约束](#测试硬约束) 批量验证；依赖前项结果的修复才逐项推进，不为每条发现或每次编辑固定启动一轮测试。若建议破坏现有行为、超范围、违背 YAGNI 或缺上下文，用代码、契约或测试有据反驳并交主代理核实；主代理兼作者时，排除、降级、转风险或移出仍按 [编排规则](orchestration.md#审查和修复) 交独立确认。用户已有架构决策优先。

## 测试硬约束

新增测试先核对覆盖缺口，说明能拦截哪种已有检查未覆盖的合理错误；用户或项目的覆盖要求仍须满足。预期值来自需求、契约或独立参考，不复制实现计算期望、不只验证 mock 按预设返回、不为覆盖率堆测试。

测试粒度按可独立失败的可观察行为、公共契约和业务不变量；同语义数据变体优先参数化，不按私有 helper、内部调用顺序或每行代码拆测。只 mock 外部边界（网络、时钟、第三方服务、命令行工具和环境能力），不 mock 被测对象内部结构。低影响文案、样式与纯声明配置不新增只匹配文本的测试。

## 测试选择

“最小充分”指能拦截目标行为回归的最小集合，不指测试越碎越好；涉及跨层行为时必须覆盖实际调用链，私有 helper 的孤立测试不能替代该验收。

- **可观测性优先**：断言用户可感知的结果（命令输出、退出码、界面状态、文件与外部系统副作用），优先通过 CLI、界面或公共 API 驱动，内部入口只作最小驱动。无法从可感知行为观测时才 mock，且只 mock 外部边界，不 mock 被测代码内部结构。

现有测试不足以证明目标行为，或项目反复需要人工验收且缺可复用操作方法时，按 [项目验证方法](verification.md) 补足实际入口操作与取证；已有充分检查直接复用。

- **新功能与非平凡行为**：先按验收行为写最小充分失败测试（红），确认失败原因是“功能缺失”而非语法错误，再写最小实现（绿）并重构；一组同语义输入可在同一轮红绿中验证，不为每个参数或实现步骤单开红绿循环。原型、生成代码、纯配置与低影响文字/样式除外（无法构造失败测试时依契约或静态链路分析并记未确认条件）。
- **Bug 修复**：先构造复现原症状的回归检查并确认修复前失败；无法复现时依明确契约或静态链路分析并记未确认条件，不把推测当已证实根因。已有有效红测直接复用，不为补历史 TDD 回滚用户已有工作（需验旧版时在隔离副本运行）。
- **覆盖与高风险**：非平凡逻辑须有覆盖验收、边界、错误处理或业务不变量的有效行为证据；已有测试充分覆盖时直接复用，不要求每次改动至少新增一个测试。不镜像实现，不引入无关测试框架；测试数量和覆盖率不能单独证明质量。触及 [高风险边界](routing.md#高风险边界) 时核对失败分支、授权边界、重复执行与版本共存，用隔离数据、禁碰生产数据。
- **重构与性能**：纯重构记录基线通过与改后行为保持，不要求红测；需要明确目标结构、迁移步骤或补足等价证据时按 [重构方法](refactoring.md) 执行。性能优化先取可比基线，注明数据量、环境、负载与测量法，不凭主观宣布加速。优先跑项目既有检查，仅在范围、项目要求、新失败或未解决疑点需要时扩大测试；环境失败与代码失败分开，不盲改代码修工具故障。

性能比较须确认计时范围内实际完成了目标工作，校验结果正确并记录成功量与错误量；保持工作负载、构建配置与环境可比，按需重复或交错测量，报告带单位的指标、统计口径、运行次数与波动。差异未超过测量波动时不宣称提升；仅单次测量时说明局限，微基准收益不能直接推导为端到端收益。

## 验证调度

先选择与验收匹配的最小充分检查，优先项目既有脚本。稳定快照上独立、无资源冲突的检查批量并行；红测→实现→绿测、构建→依赖产物的验收按顺序。共享数据库、端口或输出目录优先廉价隔离，无法隔离的冲突组串行，其余并行；不为并行引入框架。

检查不少于 3 项，或按既有记录预计串行耗时超过 60 秒时，在上下文简记批次、依赖和适用的资源限制；60 秒是调度说明阈值，不是性能收益结论。普通 lint 加单测直接运行，不要求 PID 时间档案、并发上限论证或能力探测。工具已知限制按说明执行，能力未知如实写未知，不虚称“不支持”。若要证明并行或加速收益，使用工具事件或各检查的实际起止记录，串行包装不算并行。

可能阻塞的命令带硬超时；超时或同一验证思路连续两次无新证据则换方案。仅当测试依赖 pty、真实网络、无头浏览器等外部能力且可用性未知时，做一次最长 15 秒探测；失败改用合法替身或进程内方案并说明限制。不设计依赖多轮交互输入的自动测试。

每批期间停写被验证代码，收齐各项退出状态、日志与产物后再处理失败，某项非零不能掩盖其他结果。有效证据复用，只在改动、新失败或未决疑点使其失效时重跑或扩大范围；交付仍须完成项目规定的检查。

## 证据

记录实际命令、工作目录、退出状态、关键输出与对应版本/快照；未完成项不得混入通过结果；调度记录按上节阈值保留，性能声明另附实际测量。长输出存可回查位置，上下文读摘要、片段与路径；错误堆栈、精确参数和契约保留原文，摘要不足回查全文。凭证脱敏并受权限保护，敏感原内容不入共享交接。子代理报通过时主代理核对可查输出与当前 diff，证据不足才补跑。

回归测试须记修复前失败、修复后通过两次输出（仅跑过一次不证能拦回归）。同版本、同环境的有效检查可复用，不按消息或审查轮次重复全量；受后续改动影响的检查必须重跑，未受影响结果不称覆盖新行为。构建通过、lint 通过、测试通过、验收满足分别判定。

## 完成边界

- **quick 已完成**：目标行为满足，按任务类型完成验证（新增/可复现缺陷具红绿记录，重构具行为保持记录，配置与无法动态复现场景具对应检查及限制说明），通过 [交付前三项微自检](../SKILL.md#开始工作)，明确只做自查。
- **normal 已完成**：符合 [normal 完成条件](routing.md#normal-流程)，有覆盖最终版本的独立定向审查（首轮无必关项，或一次局部 P2 修复后经定向复审确认关闭）；能力受阻则报告缺口。
- **full 闭环完成**：目标行为满足、验证通过且范围无遗漏；最终独立审查覆盖完整任务变更，范围内确认缺陷均关闭，关键风险和验收均有证据。不影响验收的 P3 可列为未实施建议（不称“所有发现已处理”）；影响验收项不得按建议跳过。
- **实现已完成、验证受阻**：代码已写但必要检查无法运行或独立审查未完成，说明具体缺口，不称闭环完成。
- **部分完成/待确认**：存在未决缺陷、验收缺口、潜在 P0/P1 待验证风险，或预算耗尽仍有待处理项；用户接受已知风险时保留记录，不改写为无缺陷。

收尾说明结果、必要验证与实质限制；不凭测试数、模型名或无发现推导“保证可发布”。
