# 项目验证方法

用于现有测试不足以证明目标行为，或同一项目反复需要人工验收、缺少可复用操作方法时。已有充分行为检查直接复用，简单任务不额外加载本模块。这里只补如何操作产品并取得证据；风险分流、测试粒度、命令超时、调度、证据记录与完成判定沿用 [SKILL.md](../SKILL.md) 和 [execution.md](execution.md)，不新增审批或审查闭环。

## 先从项目取得操作依据

调查当前任务对应的用户入口，复用项目已有测试、启动脚本、文档及宿主可用的 UI/CLI/API 驱动。先核对真实命令、配置、数据与身份前置条件；代码和现有约定无法确认且会改变验收结果的条件，再按 [planning.md](planning.md#选项式澄清) 提问。缺少驱动能力时报告缺口，不通过另开工具绕过宿主限制。

验证范围围绕当前验收行为及实际受影响入口选择，不为一次任务建立全项目功能地图。验证依赖应用启动时，就绪须意味着目标操作可用，包括必要的迁移、种子数据与鉴权；进程存在、端口响应或数据库健康检查单独通过不代表该功能已经就绪。启动失败时先区分产品故障、环境问题和操作说明过期；修复仍受本次授权与范围约束。

## 最小验证契约

在当前上下文说明以下实际需要的信息；已有说明用路径引用，不重复抄写。工具只支持部分操作时，明确对应的未验证范围。

| 内容 | 必须能回答的问题 |
| --- | --- |
| 启动与就绪 | 用什么命令、配置和数据启动？什么状态证明目标功能可操作？短命令行程序可直接运行，无须另起常驻服务 |
| 实例检查 | 如何确认版本或构建、目标实例、端口归属与测试身份正确？沿用用户实例须有既有授权，不因进程健康就获得操作权限 |
| 用户入口与动作 | 从哪个真实入口执行哪些操作？UI 优先语义标识，CLI/API 使用项目实际命令或路由；不用内部状态赋值或仅测试可用的捷径代替目标用户路径 |
| 预期结果 | 什么输出、界面状态、文件或数据变化证明成功？依据用户要求或既有契约，同时核对与验收有关的外部副作用 |
| 证据位置 | 如何记录动作与结果的对应关系，保存命令输出、响应、截图或必要副作用证据？沿用 [证据规则](execution.md#证据)，不只保留一张无法归因的最终截图 |
| 清理 | 哪些进程、实例和临时数据属于本次验证，如何结束或移除？证据保存到不会随运行环境清理而消失的位置 |

## 操作、取证与恢复

- 使用可隔离的端口、数据目录或测试账号；无法隔离的共享实例按调度规则串行操作，不同时驱动同一 UI 或数据集。真实服务调用、数据写入或对外消息仍须符合既有授权；无法安全执行时报告受阻，使用替身只能证明对应边界内行为。
- 首次操作前核对实例与前置条件；出现异常后重新检查。进程健康但界面或业务状态卡住时，先恢复已知状态或重启本次创建的实例，再继续；不在未知状态上反复点击或重试。
- 观察实际动作、可见结果和相关副作用；对 dry-run 或测试模式也核对它实际跳过了什么，不凭名称认定没有写入、网络请求或其他外部影响。
- 成功与失败尝试都清理已不再需要的本次进程和临时状态；按记录的实例或进程身份清理，不按通用进程名批量终止。共享实例只移除本次残留，不关闭用户实例或删除用户数据。清理遵守原授权及宿主权限，证据始终保留并确认仍可读取。
- 必要入口不可达时记录前置条件、尝试路径和阻塞原因，按 [完成边界](execution.md#完成边界) 报告实际状态；不能把不可达或未执行计为通过。

## 复用与维护

同一方法确需反复使用时，才把已跑通的步骤、前置条件与清理方法保存到项目已有文档或脚本位置；一次性检查保留当前任务证据即可，不自动创建新技能、验证框架或定期任务。新增可复用操作方法后，在允许范围内实际跑通目标路径，取证并清理；未经执行的说明标为草稿或未验证，不称已可用。方法调整后重验受影响步骤，复用仍有效的其他证据。

维护时区分三类变化：操作说明与当前实现不符，修正说明；产品行为符合契约但驱动失效，修正驱动并重跑；产品行为违反契约，报告或在已有授权内修复产品。不得降低预期、跳过入口或修改说明来掩盖产品回归。交付仅说明已验证的入口与结果、证据位置、清理状态及未验证条件，不扩展为全项目验收结论。
