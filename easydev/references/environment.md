# 环境、模型与工作区

涵盖模型配置、宿主适配、能力降级、基线安全与工作区隔离。

## 模型配置

仅在真正分派或用户要求查看/调整配置时读取；配置只控制被委派角色，不改变主代理模型。

### 来源优先级
对话字段覆盖 > 对话指定文件 > 项目根 `.easydev/models.json` > 用户配置（macOS/Linux 为 `~/.config/easydev/models.json`，Windows 为 `%APPDATA%/easydev/models.json`）> 内置默认。
- **文件不合并**：选定最高优先级的基础文件后再应用对话局部覆盖。选中配置无效或不可读时暂停相关分派并报错，不静默回退。
- **内置默认**：developer、reviewer、designer 均为 `inherit`，`upgrades` 为空。

### 字段规范
- `developer` / `reviewer`：必需对象，各含 `model` 和 `reasoning_effort`。
- `designer`：可选对象，省略等同两字段 `inherit`。仅启用设计环节时使用；inherit 由主代理设计，具体模型不可用时暂停设计分派，不静默回落。
- `upgrades`：可选数组，最多两项；每项含 developer 和 reviewer（不含 designer），每阶段至少一个角色的模型或深度不同于前一阶段。
- `model`：`inherit` 遵循宿主继承；其他值须与宿主支持的完整 ID 一致。
- `reasoning_effort`：`inherit` 或 `none / minimal / low / medium / high / xhigh / max / ultra`。

### 分派与生效核对
分派前记录配置来源与对话覆盖。实际模型与深度先取工具返回值，其次可访问的运行记录；确无记录时标未知，不把请求值当成已生效。角色升级受任务总计 3 次修复尝试约束，升级不加审核轮次。

## 宿主适配与能力降级

仅在委派能力不确定、需要核对模型/深度支持、调用失败或需要能力降级时读取。

- 用户指定的模型、供应商与禁止委派约束优先。配置指定的模型无法满足时暂停相关分派并报告受阻，不静默改用继承模型。
- 模型不可用、限流或网络故障先分类，不擅自切换供应商或无意义重试。
- 跨供应商交接只给必要代码与证据，不发送凭证或完整会话。

### 能力降级与审查包
- **不同实例且上下文独立**：正常独立审查。
- **不同实例但继承上下文**：按原档位审查，标“独立实例、上下文隔离受限”；审查与实现的实例分离仍须满足。
- **同一实例或无委派能力**：在授权内实施与对抗式自查，标“自查（非独立）”；不得称 normal 独立审查通过或 full 闭环完成。
- **审查包**：自查降级必须交付可供人工或其他会话核对的审查包（保存在任务目录）：原始要求/验收、基线与当前版本、完整任务 diff、直接调用方与关键契约材料、验证命令与结果证据、未决风险与已用预算。审查包交付不等于缺陷已关闭。

## 基线与敏感快照

工作区不干净、存在未跟踪或敏感文件、无 Git，或需要跨会话恢复时使用：

- 开工前用命令采集状态（`git status --short --untracked-files=all`），记录基线提交。干净已跟踪文件直接复用 Git 基线；已有修改、未跟踪或无 Git 时，在任务目录 `baseline/` 按仓库规范相对路径保存首次原内容（不存只读哈希，后续编辑不覆盖首次基线）。
- 仅覆盖本任务范围，不复制全仓或无关凭证；归属不明先核实，禁止为整理基线擅自 `stash`、`reset`、`checkout`。
- **敏感原内容保护**：敏感文件（如含凭证的 `.env`）**严禁写入公开/同步的 artifact 目录**。使用确认不同步的系统临时目录，设置权限 `0700`、文件 `0600`；逐级核验父目录链为非符号链接的真实目录；目标已存在时必须确认为非符号链接的普通文件。无法确认保护条件时暂停写入。

## 任务目录与恢复

- 非敏感记录优先使用宿主 artifact/scratch 目录；否则使用系统临时目录 `easydev/<repo-id>/<task-id>/`。
- 账本为 `ledger.md`，非敏感基线放 `baseline/`，探针产物放 `spike/`（标 `throwaway`），设计环节产物放 `design.md`（含 `design.vN.md`，不是 throwaway，未归档前保留）。
- 恢复由交接提供账本路径；临时目录已清理时先核实基线与预算，不默认为新任务。确认无需恢复后按宿主权限清理本次产物，不将快照移入产品仓库。

## 工作区隔离与分支收尾

在任务需要隔离、用户要求或长任务需要独立工作区时使用：

- **创建**：优先使用宿主原生工作树工具，回退 `git worktree add`。基准分支按任务指定或宿主默认分支，不静默使用 main。创建前检查当前工作区，有未保护改动时先记录并迁移原状态。创建失败不绕过限制。
- **收尾与集成**：
  1. 先跑通完整验证，测试通过后才进入集成。
  2. 核对授权基线：未获用户明确授权前，呈现选项并等待用户选择（本地合并 / 推送并创建 PR / 保留现状），不代为决定。
  3. 本地集成优先在独立集成分支完成并验证，再快进更新目标分支；合并后重跑验证，失败时停止并安全回退。
  4. 推送、创建 PR、发布必须有用户明确授权。
  5. 清理仅针对本任务创建的工作树，优先原生工具，回退 `git worktree remove`；绝不 `--force` 或擅自丢弃分支。
