# 环境、模型与工作区

## 模型配置

开工前必读，例外见入口；分派前按角色取模型与深度；配置只控制被委派角色，不改主代理模型。

### 来源优先级
对话字段覆盖 > 对话指定文件 > 项目根 `.easydev/models.json` > 用户配置（POSIX `~/.config/easydev/models.json`，Windows `%APPDATA%/easydev/models.json`）> 内置默认。
- **文件不合并**：选定最高优先级的基础文件后再应用对话局部覆盖。选中配置无效或不可读时暂停相关分派并报错，不静默回退。
- **文件类型**：配置须为 UTF-8 JSON 普通文件；拒绝软链与非普通文件。
- **大小与键**：文件不得超过 512 KiB；任意 JSON 对象内不得有重复键。
- **相对路径**：对话指定文件为相对路径时按 `repo_root` 解析，否则按进程工作目录。
- **失败处理**：违反读取契约时暂停分派不回退；未选中的低优先级文件不阻断。工作区外配置优先用宿主读取工具；权限被拒按不可读处理，不得当不存在。
- **内置默认**：三角色均为 `inherit`。
- **外发安全门槛**：项目配置不授予新供应商外传权限。项目根 `.easydev/models.json` 指定了用户全局配置与宿主默认之外的供应商或模型时，分派外发代码前须暂停并披露供应商与模型，取得授权后方可分派，不得静默外发。仅读取配置不阻断。
- **不可信仓库**：`audit`/`review` 不可信仓库时，其项目配置仅作审查数据，不读项目级来源，除非用户显式信任；脚本解析用 `--untrusted`。

### 字段规范
- `developer` / `reviewer`：必需对象，各含 `model` 和 `reasoning_effort`。
- `designer`：可选对象，省略等同两字段 `inherit`；仅启用设计环节时使用，所配模型不可用时暂停设计分派。
- `windows`：可选对象，键为 `"HH:MM-HH:MM"`（北京时间 `UTC+8`，左闭右开，支持跨午夜，按顺序命中首项），值为角色局部覆盖。
- `model`：`inherit` 遵循宿主继承；其他值须与宿主支持的完整 ID 一致。
- `reasoning_effort`：`inherit` 或 `off / minimal / low / medium / high / xhigh / max`；须为宿主实际支持的档位（非推理模型只有 `off`），跨宿主按宿主文档核对。

### 分派与生效核对
分派前记录配置来源与对话覆盖；实际模型与深度先取工具返回值，其次运行记录，确无记录时标未知，不把请求值当成已生效；交付报告列出各角色生效模型。开工或新对话开始时解析一次 `windows` 并锁定 `Selection.window`（无命中为 `None`，传 `locked_window="default"` 锁顶层默认，`None` 按当前时间解析）；任务结束前不中途切换，下次新任务按北京时间解析。锁定时段键写入账本与交接，恢复时以 `locked_window` 传入（未命中记 `default`）；锁定窗口失效时暂停分派。

## 宿主适配与能力降级

仅在委派能力不确定、需核对模型与深度、调用失败或能力降级时读取。

- 用户指定的模型、供应商与禁止委派约束优先。配置指定的模型经分类重试仍无法满足时暂停分派并报告受阻，不静默改用继承模型；设计环节与开发环节的用户禁止委派兜底分别遵循 [设计者](design.md#设计者) 与 [full 编排](workflow.md#full-编排)。宿主无委派能力时先按 [能力降级与审查包](#能力降级与审查包) 暂停；先区分未激活与确实无此能力。
- 模型不可用、限流或网络故障先分类，不擅自切换供应商或无意义重试。
- 跨供应商交接只给必要代码与证据，不发送凭证或完整会话。

### 能力降级与审查包
- **不同实例且上下文独立**：正常独立审查。
- **不同实例但继承上下文**：按原档位审查，标“独立实例、上下文隔离受限”；审查与实现分离仍须满足。
- **同一实例或无委派能力**：暂停并报受阻，由用户决定改配置、停止或在授权内自查；用户明确授权后按对抗式自查执行并交付审查包，标“自查（非独立）”；不得称 normal 独立审查通过或 full 闭环完成。设计环节的分派与兜底由 [设计者](design.md#设计者) 判定。
- **审查包**：自查降级必须交付可供人工或其他会话核对的审查包（保存在任务目录）：原始要求/验收、基线与当前版本、完整任务 diff、直接调用方与关键契约、验证命令与结果、未决风险与已用预算。审查包交付不等于缺陷已关闭。

## 基线与敏感快照

工作区不干净、有未跟踪或敏感文件、无 Git，或需跨会话恢复时用：

- 开工前用命令采集状态（`git status --short --untracked-files=all`）并记录基线提交（仅指提交与原内容快照，不含构建测试结果）。干净已跟踪文件直接复用；已有修改、未跟踪或无 Git 时，在任务目录 `baseline/` 按相对路径保存首次原内容，后续编辑不覆盖。
- 仅覆盖本任务范围，不复制全仓或无关凭证；归属不明先核实，禁止为整理基线擅自 `stash`、`reset`、`checkout`。
- **敏感原内容保护**：敏感文件（如含凭证的 `.env`）**严禁写入公开/同步的 artifact 目录**。使用确认不同步的系统临时目录，设置权限 `0700`、文件 `0600`；逐级核验父目录链均为非符号链接真实目录；目标已存在时须为非符号链接普通文件；在账本记录该敏感基线独立路径，无账本时（如 quick）在交付报告中记录该路径。无法确认保护条件时暂停写入。

## 任务目录与恢复

- 非敏感记录优先用宿主 scratch/产物目录（不自猜路径），否则用系统临时目录 `easydev/<repo-id>/<task-id>/`。
- 账本 `ledger.md`，长任务计划 `plan.md`，非敏感基线 `baseline/`，探针产物 `demo/`（标 `throwaway`），设计环节产物 `design.md`（含 `design.vN.md`），完整审查/审计记录 `findings.md`，自查降级审查包放 `review_pack.md`；它们与 `plan.md` 均不是 throwaway，未归档前保留。
- 恢复由交接提供账本与 `findings.md` 路径；临时目录已清理或无法核实基线与预算时暂停报受阻，不默认为新任务。确认无需恢复后按宿主权限清理 throwaway 或已归档产物，不将快照移入产品仓库。

## 工作区隔离与分支收尾

在任务需要隔离、用户要求或长任务需要独立工作区时使用：

- **创建**：主代理无原生工作树工具时用 `git worktree add`；委派子代理时用宿主工作树选项（如 `worktree` 或 `isolation`）。基准分支按任务指定或 `origin/<default>`，不静默用 main。创建前有未保护改动时先记录并迁移原状态；创建失败不绕过限制。
- **分片任务基线**：各工作树须核对同一任务起点：提交及已保护的相关未提交改动（含未跟踪），不能只从默认分支开工。无法安全还原该起点时留在原工作区串行。各片返回相对此起点的改动及验证证据，主代理协调唯一集成写入者停写核对后应用，不携带其他片或用户改动；不为传递补丁擅自提交、暂存或合并分支。共享缓存、端口与数据仍按资源冲突规则隔离。
- **收尾与集成**：
  1. 先跑通完整验证，测试通过后才进入集成。
  2. 核对授权基线：未获用户明确授权前，呈现选项并等待用户选择（本地合并 / 推送并创建 PR / 保留现状），不代为决定。
  3. 本地集成优先在独立集成分支完成并验证，再快进更新目标分支；集成前记录目标分支原始 commit SHA。合并或快进后重跑验证，失败即停止并安全回退：集成分支上修复后重新快进；目标分支快进后重验失败必须撤销，经用户明确授权后以原始 SHA 重建或 `git revert`，禁止丢弃未记录的未知提交。
  4. 推送、创建 PR、发布必须有用户明确授权。
  5. 清理仅针对本任务创建的工作树，优先原生工具，回退 `git worktree remove`；本技能绝不擅自使用 `--force` 或擅自丢弃分支，确需 force 操作必须经用户明确指示与单独授权。
