# 环境、模型与工作区

## 模型配置

开工前必读，例外见入口；分派前按角色取模型与深度；配置只控被委派角色，不改主代理模型。

### 来源优先级
对话字段覆盖 > 对话指定文件 > 项目根 `.easydev/models.json` > 用户配置（POSIX `~/.config/easydev/models.json`，Windows `%APPDATA%/easydev/models.json`）> 内置默认。
- **文件不合并**：选定最高优先级的基础文件后再应用对话局部覆盖。选中配置无效或不可读时暂停相关分派并报错，不静默回退。
- **文件类型与大小**：须为 UTF-8 JSON 普通文件（拒软链与非普通文件），≤512 KiB，任意 JSON 对象内禁重复键。
- **相对路径与失败处理**：对话指定相对路径按 `repo_root` 解析，否则按工作目录。违反契约暂停分派不回退；未选中低优先级文件不阻断。工作区外配置优先用宿主读取工具；权限被拒按不可读处理，不得当不存在。
- **内置默认**：三角色均为 `inherit`。
- **外发安全门槛**：项目配置不授予新供应商外传权限。项目根 `.easydev/models.json` 指定了用户全局配置与宿主默认之外的供应商或模型时，分派外发代码前须暂停并披露供应商与模型，取得授权后方可分派，不得静默外发。仅读取配置不阻断。
- **不可信仓库**：`audit`/`review` 不可信仓库时，其项目配置仅作审查数据，不读项目级来源（除非用户显式信任）。

### 字段规范
- `developer` / `reviewer`：必需对象，各含 `model` 和 `reasoning_effort`。
- `designer`：可选对象，省略等同两字段 `inherit`；仅设计环节使用，不可用时暂停设计分派。
- `windows`：可选对象，键为 `"HH:MM-HH:MM"`（北京时间 `UTC+8`，左闭右开，支持跨午夜，按序命中首项），值为角色局部覆盖。
- `model`：`inherit` 或宿主支持的完整 ID。
- `reasoning_effort`：`inherit` 或 `off / minimal / low / medium / high / xhigh / max`（须为宿主支持档位，非推理模型只有 `off`）。

### 分派与生效核对
分派前记配置来源与对话覆盖；实际模型与深度依次取工具返回、运行记录，确无则标未知，不把请求值当生效；交付报告列出各角色生效模型。开工或新对话解析一次 `windows` 并锁命中时段键（无命中记 `default`），任务结束前不切；写入账本与交接，恢复沿用，锁定窗口失效暂停分派。

## 宿主适配与能力降级

仅委派不确定、核对模型/深度、失败或降级时读。

- 用户指定模型、供应商与禁委派优先。所配模型经分类重试仍不可用时暂停报受阻，不静默改继承；禁委派兜底见 [设计者](design.md#设计者) 与 [full 编排](workflow.md#full-编排)。无委派能力按 [能力降级与审查包](#能力降级与审查包) 暂停；先区分未激活与无能力。
- 模型不可用、限流或网络故障先分类，不擅换供应商或盲目重试；跨供应商交接只给必要代码与证据，不传凭证或完整会话。

### 能力降级与审查包
- **不同实例且上下文独立**：正常独立审查。
- **不同实例但继承上下文**：按原档位审查，标“独立实例、上下文隔离受限”；审改分离仍须满足。
- **同一实例或无委派能力**：暂停报受阻，交用户定改配置、停止或授权自查；获授权后对抗自查并交审查包，标“自查（非独立）”，不称 normal 独立审查通过或 full 闭环完成。设计兜底见 [设计者](design.md#设计者)。
- **审查包**：自查降级须在任务目录交审查包（需求/验收、基线与版本、完整 diff、直接调用方与契约、验证命令与结果、未决风险与预算）；交付不等于缺陷关闭。

## 基线与敏感快照

工作区不干净、有未跟踪/敏感文件、无 Git 或跨会话恢复时用：

- 开工用 `git status --short --untracked-files=all` 采状态并记基线提交（不含构建测试结果）。干净已跟踪文件直接复用；已有修改、未跟踪或无 Git 在任务目录 `baseline/` 按相对路径存首次原内容，后续不覆盖。
- 仅覆盖任务范围，不复制全仓或无关凭证；归属不明先核实，禁擅自 `stash`/`reset`/`checkout`。
- **敏感原内容保护**：敏感文件（如 `.env`）**严禁写入公开/同步 artifact 目录**；须放确认不同步的系统临时目录（目录 `0700`、文件 `0600`），逐级核验父目录链非符号链接、目标若存在须为非符号链接普通文件；账本（无账本则在报告）记该独立路径，无法确认保护条件暂停写入。

## 任务目录与恢复

- 非敏感记录优先宿主 scratch/产物目录（不自猜路径），否则系统临时目录 `easydev/<repo-id>/<task-id>/`（Antigravity 禁写 `/tmp`）。
- 产物：`ledger.md`、`plan.md`、`baseline/`、`demo/`（标 `throwaway`）、`design.md`（含 `design.vN.md`）、`findings.md`；自查降级审查包放 `review_pack.md`；它们与 `plan.md` 均不是 throwaway，未归档前保留。
- 恢复由交接给账本与 `findings.md` 路径；临时目录已清或无法核基线与预算暂停报受阻，不默认新任务。确认无需恢复按权限清理 throwaway 或已归档产物，不移入产品仓库。

## 工作区隔离与分支收尾

需要隔离、用户要求或长任务需独立工作区时用：

- **创建**：无原生工具用 `git worktree add`，子代理用宿主隔离选项；基准按任务指定或 `origin/<default>`，不静默用 main。未保护改动先记录迁移，失败不绕过限制。
- **分片任务基线**：各工作树核同一任务起点（提交及已保护的相关未提交改动（含未跟踪）），不只从默认分支开工；无法安全还原留原工作区串行。各片返相对起点改动与证据，由唯一集成者停写核对应用，不带他片或用户改动；不为传递补丁擅自提交、暂存或合并分支。共享缓存、端口与数据仍须隔离。
- **收尾与集成**：
  1. 先跑通完整验证再集成。
  2. 核授权：未获用户明确授权前呈选项（本地合并 / 推送创建 PR / 保留现状），不代为决定。
  3. 优先独立集成分支验证后快进目标分支；集成前记目标原始 SHA。合并/快进后重验失败即停：集成分支修后重快进；目标分支快进失败须经用户明确授权以原始 SHA 重建或 `git revert`，禁丢未记录提交。
  4. 推送、创建 PR、发布须用户明确授权。
  5. 仅清本任务工作树（优先原生工具，回退 `git worktree remove`）；绝不擅用 `--force` 或丢弃分支，确需 force 须用户单独授权。
