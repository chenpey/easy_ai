# 重构

用于需要明确目标结构、迁移步骤或补足行为保持证据的重构；简单局部重命名、移动且既有检查充分时，使用 [quick 核心](../SKILL.md#quick-执行核心)。本模块只补重构方法，沿用入口的 quick/full 分流、单一写入者、修复与审查预算、授权和完成边界；审查标准仍以 [review.md](review.md) 为准。

## 行为边界与基线

修改结构前明确保留的契约与已授权变化：输入输出、错误类型与退出状态、外部副作用，以及与任务有关的顺序、状态归属、资源生命周期和性能约束。只读设计或计划只交付方案与验证方法，不自动开始实现。

- 既有行为检查充分时直接复用，先确认修改前结果；覆盖不足时，为具体风险补特征测试（记录既有可观测行为）、快照或旧新版对照检查，再移动结构。类型检查和 lint 不能单独证明行为保持。
- 纯重构采用“基线通过 → 重构后仍通过”的证据，不为 TDD 制造红测。新增检查仍遵守 [测试硬约束](../SKILL.md#测试硬约束)，不用内部 helper、调用次数或代码文本锁定实现结构。
- 既有行为是对照材料，不自动成为正确需求。已知 Bug 与契约冲突单列；纯重构保持其可观察现状时标明限制，不把错误写成永久业务要求。未授权的修复不夹带实施；已授权的混合任务分别记录行为修正与结构变化的验收，按依赖和风险安排顺序，不强制先重构再修 Bug。安全缺陷按其影响优先处理。
- 基线检查失败时区分既有失败、环境受阻与本次引入的回归；已有有效证据可复用，必要行为无法验证时报告缺口，不用放宽断言或修改预期换取通过。无动态能力时可做静态契约分析，但不称已证等价。

旧版来自任务开始时的真实内容；有用户改动时不能只用 HEAD 代替。基线保存与隔离遵守 [baseline-safety.md](baseline-safety.md) 和 [worktree.md](worktree.md)，不回滚用户工作来构造对照。

## 目标结构与收益

先指出具体维护问题、代码位置和目标结构，再决定改动。目标应能从依赖关系、状态表示或调用链检查，不以“更优雅”、文件数、代码行数或抽象层数为验收。

| 当前问题 | 可检查的结构目标 |
| --- | --- |
| 同一业务规则散落多个入口 | 保留一个权威实现，原入口全部使用它 |
| 业务层直接依赖具体基础设施 | 在现有边界内分离职责，业务逻辑不再依赖该具体实现 |
| 多个标志位组合出互相矛盾的状态 | 显式表达合法状态与转换，减少非法组合 |
| 增加一种业务类型需同步多处分支 | 集中该变化的归属，减少必须共同修改的位置 |

复用现有结构，只增加解决已确认问题所需的抽象；检查是否把复杂度转移到了布尔开关、隐藏依赖、包装链或过大的通用接口中。目标明确时直接实施；多个实质不同且都可行的结构方案才按 [candidates.md](candidates.md) 比较，不因跨函数或文件自动启动候选评审。

## 迁移与阶段验证

按职责或调用链划分有意义、可验证的结构变化。相关修改完成后在阶段边界验证行为与契约，保持各阶段可构建、可检查；不为每个重命名或微小编辑单开全量验证。依赖与并发按 [验证调度](execution.md#验证调度) 执行。

迁移前核对所有受影响入口，除静态调用方外，按实际机制检查动态注册、字符串与配置引用、导出、文档示例、序列化名称和持久数据标识。符号改名不自动授权改变外部名称或数据格式。

| 发布与调用方条件 | 迁移方式与删除条件 |
| --- | --- |
| 内部接口，调用方全部可控且一起发布 | 同步迁移调用方，检查无残留引用后删除旧入口 |
| 公共接口、独立发布客户端或滚动部署 | 按兼容承诺分阶段迁移；必要兼容层写明使用者、退出条件及验证方式，不能因仓库内无引用就判可删 |
| 数据格式或数据库迁移 | 明确新旧版本共存、读写顺序、失败恢复与回滚或前向修复；按入口风险规则进入 full |

清理限定在本任务引入或因迁移失效的代码、测试、配置与说明。保留仍有使用者的兼容路径，删除已确认无用的旧入口和迁移脚手架；尚不能删除的记录原因与退出条件。发现范围或风险实质扩大时携已有证据按入口升级，不重置预算。

## 旧新版差分验证

较大的解析、计算、序列化或数据转换重构，可用同一组输入驱动旧版与新版，比较可观察输出、错误与副作用；已有充分行为证据时不强制增加对照工具。

1. 固定输入、初始状态与可比环境；时钟、随机源和外部依赖按需控制，只替代外部边界，不替代被测内部结构。有副作用时使用各自隔离的临时数据，不重复操作生产数据或外部真实系统。
2. 对比规则来自既有契约与已授权变化。只归一化确认不属于契约的时间戳、临时路径等差异；不能随意忽略顺序、错误、字段或副作用。数值容差须有单位与契约或数值依据，不能为通过对照临时放宽。
3. 差异出现时定位原因，区分允许变化、既有缺陷和新回归；旧新版一致仍需核对业务不变量，不能用共同错误自证正确。
4. 记录旧新版标识、输入与环境、比较规则、命令与结果。结论限定在已覆盖场景；抽样、快照或差分通过不代表全部输入上等价。证据保存与命令超时沿用 [execution.md](execution.md)。

## 自查、审查与交付

对照修改前声明的目标核对两类证据：行为和兼容承诺得到保持；依赖、重复决策或状态复杂度确有改善。只改变文件布局、增加转发层或把复杂度搬到调用方时，说明具体收益是否成立，不凭“测试通过”宣称结构目标完成。

审查时追踪状态与资源归属、错误传播、性能约束和旧入口的删除条件；以具体契约或维护代价说明问题，不把风格偏好当缺陷，不另建评分或审核闭环。

交付说明改变了什么结构、改善了哪个具体问题、行为保持证据与覆盖范围、已授权行为变化，以及兼容层残留和未验证条件。必要检查受阻或结构目标未达成时，按 [完成边界](execution.md#完成边界) 报告实际状态；不以无关重写补偿收益不足。
