# 流程编排

主代理独占流程状态：分流、分派、预算与宣布完成。子代理只回报新证据。

## 分流判定

仅要 design/plan/debug/review/audit/demo 只交产物，不扩为实现。用户指定档位、范围与授权优先，但低于高风险所需时不得静默降档；交互环境先暂停披露高风险与缺独立审查风险，获明确放宽确认后方可降档并断言未覆盖风险；非交互或未获确认按 full 执行并报偏离。

读目标、直接调用方、测试及发布/数据边界后，风险分三态：

- **已排除**：有推翻风险假设的证据（如调用方同发、接口不变、不改鉴权）；搜索无命中不排除动态调用或外部客户端。
- **已确认涉及**：指出入口、不变量与失败方式。
- **尚未核实**：有线索但关键条件不明；最小调查后仍不明进 full，不把“未看”当“已排除”，不穷尽无据假想。

**第二视角信号**（命中任一即具备）：

1. 改动行为无现成检查拦回归（「现成」指改动前已存在且有效，新增的测试不算；纯新增、展示文案与注释不命中，期望仍溯源需求或独立契约）。
2. 被 ≥2 个独立调用方/消费方依赖。
3. 改共享契约（接口、配置或数据语义），且存在未改使用方。
4. 用户要求独立审查。

| 路径 | 条件 | 完成方式 |
| --- | --- | --- |
| quick | 局部低风险、无第二视角信号；兼容内部机械重命名亦适用 | 入口核心：实施、验证、自查 |
| normal | 影响有界，具第二视角信号，无 full 条件 | 一次独立定向审查，至多一次局部 P2 修复复审 |
| full | 高风险边界；重大外部契约/持久数据影响（破兼容、独立发布客户端需迁移、改存量语义、难回滚）；关键不确定性仍不明；或要完整闭环 | [full 编排](#full-编排)；命中 [设计门控](design.md#启用门控) 才启用独立设计 |
| gate | 外部编排（如 `easypi`）显式指定并传入设计 | [gate 模式](#gate-模式)：先审设计再开发自验，跳内部 `r/5` 交外部终审 |

文件数、调用方数或仅提 API 不定档；有证据的兼容增量可为 normal。先分流再判门控，不反向升级。

## 高风险边界

以下是典型触发条件，不是关键词清单：

| 边界 | 需要核对的实际影响 |
| --- | --- |
| 安全、鉴权与授权 | 信任边界、身份/对象/租户权限、注入与隔离 |
| 支付、敏感数据 | 资金与账务不变量、凭证和个人数据的访问/存储/传输 |
| 并发与数据操作 | 重复执行、一致性、破坏性写入、迁移兼容及失败恢复 |
| 密码学与随机数 | 加密/签名/密钥管理、安全令牌随机性；普通展示随机数不算 |
| CI、构建、IaC、权限配置 | 凭证暴露、发布/部署权限、制品可信性、基础设施破坏 |
| 依赖与供应链 | 来源/完整性、生命周期脚本、执行权限、关键依赖行为或兼容变化 |
| 生产日志与遥测 | 密钥、令牌、个人数据是否被记录、外发或扩大可见范围 |

上表按实际影响判定：只改注释、展示文案、错误提示或不含敏感字段的日志措辞、未改变该行影响的，不因此进入 full；因其他理由已在 full 的照常执行。

## normal 流程

1. 上下文记目标、基线（含敏感基线路径）、影响依据、尝试数与已用审查数；默认不建 full 账本，长任务或跨会话恢复存最小记录。
2. 实施保持单写入者，允许只读并行；验证沿用 quick 核心；实现改动（非纯文案与注释）按 [代码质量判据](engineering.md#代码质量判据)。
3. 开工先按 [模型配置](environment.md#模型配置) 核实角色模型。不同实例按 [审查角色](roles.md#审查角色) 审完整 diff、直接调用方、相关测试与验收；交接含 `角色：reviewer` 与 roles.md 审查角色路径。diff 跨独立片可按 [并行执行](parallel.md#并行执行) 分派。
4. 首轮无必关项、验收满足、返回含「未改使用方：…（或无）」与发现方式且证据对应最终版本即交付，注明“一次独立定向审查”，不称 full 闭环；不影响验收的 P3 列未实施建议。
5. 首轮仅报局部 P2 时允许一次局部修复加一次定向复审；normal 独立审查硬上限 2 次。发起前核对历史预算，尝试已满或无复审轮次即停，不做无复审机会的修复。
6. 出现 P0/P1、非局部 P2、验收缺口、有线索未排除的潜在 P0/P1 或复审未关闭时转 full，继承发现、尝试、已用审查与候选评审（转 full 后记入 `d/3`）：首轮后记 `r=1/5`，复审后记 `r=2/5`；此前用过 full 在原轮次累加。

**局部 P2 判定**（逐条对照，确认确属局部 P2，不看措辞）：① 不触公共契约（API、CLI、配置格式、事件 schema 不变）；② 不改数据或状态语义；③ 不引新依赖、不越本任务已改文件及直接调用方；④ 非验收缺口且无未排除的潜在 P0/P1；⑤ 任一条无法用 diff、调用方或检查结果确证按非局部转 full。

审后再有实质修改，原审查不能证明最终版本；除上述一次局部修复外一律转 full 复核，纯排版不计。无独立能力按 [能力降级](environment.md#宿主适配与能力降级)，自查不算独立审查。

## full 编排

流程：明确验收（缺边界走 [深度追问](design.md#深度追问按需触发)）与基线 → 开发验证（含文档校准） → 冻结修改 → 独立审查 → 核实发现 → 有限修复 → 收口审查（有修复时为终审，同轮担复审；无修复时首审即终审） → 交付。

- **角色**：开工先按 [模型配置](environment.md#模型配置) 核实角色模型与深度。审查者须与设计者、实现者为不同实例，设计者可兼实现者。写入者按下表自上而下取第一条；上下文膨胀或满足并行条件亦可委派实现片并报告原因。

| 条件 | 写入者与标注 |
| --- | --- |
| 用户明确授权主代理自查（含禁委派；无委派能力先按 [能力降级](environment.md#能力降级与审查包) 暂停并经确认） | 主代理写入，标「自查（非独立）」并交审查包 |
| `developer` 的模型与深度均为 `inherit` | 主代理作唯一写入者、只委派审查者，标「实现=主代理」；审查仍须独立实例，不降级自查 |
| 其他（配置要求不同开发模型或深度） | 委派开发者 |
- **写入者**：同一写集同刻仅一写入者；换开发者须前任停写，预算不重置。并行见 [并行执行](parallel.md#并行执行)。
- **审查时机**：命中设计门控施工前审冻结 `design.md`（[施工闸](design.md#收敛与施工闸)）；常规实施完成后对完整变更初审，有修复时定向复审；高风险公共契约被后续阶段依赖前做阶段增量审查；修复改契约或范围时扩展复审。有修复时冻结完整 diff 后以**终审**收口，它占该轮复审的轮次、不再另起复审；无修复时首审即终审。终审覆盖验收、覆盖账与发现关闭，审查者与此前所有审查实例不同，首轮盲审、第二阶段补发清单对照仍计同一轮（[review.md#终审两阶段](review.md#终审两阶段)）。强度按 [强度分档](review.md#强度分档)，高风险最低「深」。

## gate 模式

适用于外部设计交接（如 `easypi`：外部设计 → 本代理审设计无分歧后开发 → 交外部非实现者终审）。两处既定例外须在报告披露：`d/3` 由后续实现者执行；终审由外部设计方执行（自证偏差）。高风险边界不适用本模式，仍按 `full` 保留内部独立审查。执行模型与唯一写入者由编排方指定，不按 `models.json` 另行委派 `developer`／`reviewer`。

1. **设计审查闸（`d/3`）**：传入冻结 `design.md` 路径时核对首行版本后只读审查（外部首行含 `vN` 即可，内部见 [设计产物](design.md#设计产物)），不再另存副本；仅文本传入时落盘冻结为任务目录下的 `design.md`（`v1`，修订升版）。按 [设计审查](design.md#设计审查与建议通道) 核查契约、失败路径与验收；发现高风险或设计阻塞时停写回报编排方。存在确认 P0/P1、范围内 P2、验收缺口或分歧时**严禁写代码**，停闸退回；仅余不影响验收的 P3 或无分歧开闸。修订重审计 `d/3`，用尽即停报用户。
2. **开发与自验**：严格按过闸设计实施并跑通完整验证；遇设计阻塞或高风险边界停写回报编排方，不自行切模式。
3. **停在待终审态**：跳过内部 `r/5` 代码审查，汇报设计审查结论、改动与新增文件清单及验证证据，交外部非实现者终审（不称全闭环完成）。
- **升 `full`**：保留已耗 `d/3` 与尝试数，`r` 从 0 起算；升级前 `d/3` 由实现者执行须补 1 轮独立设计审查，或经用户确认沿用并披露非独立 `d/3`；`d/3` 已用尽时停闸交用户裁决（扩预算补审 / 确认沿用并披露 / 停止），不越顶补审。

## 审查预算

| 账 | 上限 | 计入 |
| --- | --- | --- |
| 设计审查 `d/3` | 3 轮 | 设计审查、候选评审、升版重审 |
| 施工审核 `r/5` | 5 轮 | 阶段增量审查、完整初审、复审、终审（有修复时以终审替代该轮复审） |

两本账互不占用、互不退还；上限不是目标。每次独立审查占一轮，完成或受阻后更新；工具重连同次未完审查不另计，连重连 >2 次按环境受阻报。完整初审与收口轮合计预留两轮（无修复时不消费第二轮），故阶段增量审查轮数 = max(0, 3 - 已用轮数)（阶段结束时累计消耗上限，第 4、5 轮留完整初审与终审），已有 normal 审查亦占余额，多契约按依赖合批；终审第二阶段补发清单对照不另占轮次。原审查失效不退轮次；可选流水线收敛见 [并行执行](parallel.md#并行执行)，强制前置审查不得延到终审。轮次不因改称、换实例、换问题号或降级重置。

## 账本与交接

小任务记上下文；长任务或需恢复在 [任务目录](environment.md#任务目录与恢复) 存 `ledger.md`，交接给绝对路径：

```text
目标/验收/范围/授权基线（可直接执行、需确认、禁止）：
基线提交/用户已有改动/原内容位置：
阶段/写入者（并行时列片、写集与状态）/配置来源/锁定时段/实际模型与深度：
设计环节（门控命中项或不启用理由）/design.md 版本与冻结时间/设计者：
审查强度/d/3 与 r/5（占用、完成或受阻）：
并行判断（自判或用户指定片数/实际片数/判断依据 + 风险与隔离方式/宿主额度/授权来源/实际并发证据路径）：
问题 ID/证据状态/累计尝试/验证结果/关闭依据：
验证命令/退出状态/对应版本：
未覆盖/阻塞/下一步：
```

交接以摘要加路径传递：单独一行写 `角色：developer` / `reviewer` / `designer` 并附 [roles.md](roles.md) 小节路径；附目标与验收、契约、基线与版本、已完成事项与证据路径（已知切入点附符号或行号区间）、未决问题与剩余预算；设计补 `design.md` 路径、版本与 `d/3`；并行片补写集与写集外禁写。审查者可查完整 diff 与调用链；定向复审补上次版本、修复 diff 与问题号。开发者解释为待核实材料。子代理不直接向用户提问。`角色：x` 为流程标识，映射宿主实际 agent 名（如 `worker`/`reviewer`/`oracle`）。

## 审查与修复

1. 送审前主代理按基线核对完整变更（增删改、重命名、未跟踪），确认证据对应当前版本；归属不明先查不自动撤销。
2. 新审查实例同轮核验收、质量与调用链，按 [审查规程](review.md) 输出；待审执行遵 [不可信代码执行](review.md#不可信代码执行)。
3. 主代理核实每条发现：确认、排除或转待验证风险并入账。**P0/P1 排除、降级或转风险须审查者核对证据**，无复核不关闭。主代理兼作者时排除/降级须附代码、调用路径、可复现检查或需求原文：可复现交同轮复核，否则交下轮独立确认，确认前标“作者有争议、未关闭”。设计层实质改动须升版计 `d`。
4. 写入者按 [处理审查反馈](engineering.md#处理审查反馈) 修复补证；修复后收口轮由终审担复审：二阶段从原问题与修复 diff 起核关闭结论，回答修复改变了哪些前提、哪些排除路径需重纳，覆盖账已在首轮建立、按修复 diff 增补而不重建；剩余轮次充足时（剩余 `r≥2`），未收口中间复审可由原审查者同口径复核并更新覆盖账，轮次不足则直接由终审收口；全部待修完成冻结最终 diff 后须新实例终审，中间清零不替代；终审补发清单对照仍计同轮；审查者不修自己要审的版本。

| 发现 | 处置 | 末轮仍未关闭 |
| --- | --- | --- |
| 确认 P0/P1、范围内 P2 | 必须关闭补验，触发复审 | 停自动修复，报**未完成** |
| 验收缺口（含标 P3） | 必须修复，不靠降级绕过 | 报**未完成**或**部分完成/待确认** |
| 不影响验收的 P3 | 记位置与代价作未实施建议 | 正常交付并列出 |
| 待验证风险 | 列线索、条件、影响与最小确认法；full 中有具体触发路径且潜在影响为 P0–P2 的，写入者做一次最小确认（纯调查不占尝试），成立进修复，不成立记关闭证据 | 含潜在 P0/P1 报**部分完成/待确认**；未确认 P2 单列不略过 |
| 作者争议 | 附证据按第 3 条复核 | 交用户，标**作者有争议、未关闭** |
| 历史债、越界、用户接受缺陷 | 不扩任务，保留记录 | 按实际验收缺口标状态 |

## 停止与受阻

- 先分阻塞类型：缺材料补上下文、假设错重取证、边界不当调拆分，均不占修复机会。
- 末轮仍有待修缺陷报未完成，不做无复审机会的修复。需扩范围、缺关键外部信息或预算到顶即停，用户可显式扩预算沿用原账本。
- 单次 review/audit 转授权修复按分流重选路径；原只读审查只作修复前证据，不占正式轮次。修复后按实际发起的审查记账：转 quick 只自查、不记正式轮次；根因在设计且命中门控时先按设计环节记 `d=1` 并升版复审，施工后的完整初审另记 `r=1`；根因在实现记 `r=1`。normal 转 full 按 [normal 流程](#normal-流程) 继承。
- 模型不可用、权限或网络失败为环境受阻，不耗尝试；报受阻模型并继续无依赖的授权工作。
- 无待修缺陷按 [完成边界](engineering.md#完成边界) 交付，不凑轮数；中间复审清零仍须新实例终审。

## 路径升降级

风险或影响扩大时携证据升级；单次失败、跨文件或多一次调用不是升级理由，切路径不刷新预算。

降级（full→normal/quick、normal→quick）须同时满足：新证据推翻原触发条件且目标条件全成立；用户未指定原档位；无未关闭必关项、高影响待验证风险或作者争议。例外：初始分流用户指定低档位并按 [分流判定](#分流判定) 经披露后确认接受未覆盖风险的，记为用户风险接受（不视作技术反证降级），报告须断言未覆盖风险。降级只减未发生流程：已有设计、发现、尝试与轮次保留；重入 full 不退还 `d/3`、`r/5`，降级回 normal 也不重新获得已用的 normal 审查。`gate` 随风险扩大升 `full`，不降为 `normal`／`quick`。

**能力降级不等于流程降级**：缺子代理不让高风险变低风险；保留原风险判断，说明缺失保障。

## 尝试预算

同一问题全任务最多三次有新证据的候选修复尝试，quick、normal、full、gate 与换实例共用；三次仍失败或证据不足即停，报目标不变量、耦合位置、最小修复是否成立与剩余缺口，不因失败推断须重写架构。提交候选修复起计一次，下次须有新证据；纯调查与环境故障不计次且不清记录。按根因或症状识别身份，换编号不获新预算。
